# TaskCapture Android 0.2 — стеклянный интерфейс и быстрый захват
Дата: 14 октября 2026. Репозиторий: TrinetZet/TZ, ветка feat/taskcapture-android.

## Цель и согласованный объём
Влад хочет превратить скопированный в любом приложении текст в локальную задачу одним нажатием плитки TC, без формы подтверждения. Всё работает офлайн с уже встроенной Qwen3 0.6B. Обновление включает полный редизайн, анимацию успешного сохранения, управляемые статусы задач и выгрузку всех задач в Markdown с немедленной отправкой через системное меню. Windows и OCR остаются вне этого обновления.

## Выбранный подход
Расширяем существующее нативное Android-приложение, SQLite и WorkManager. Локальную модель и проверенный механизм очереди сохраняем.
Альтернативы: веб-интерфейс внутри WebView усложняет нативную интеграцию и анимации; полная смена UI-стека увеличивает объём миграции. Нативные компоненты и общая система стеклянных элементов дают нужный результат с меньшим риском.

## Захват через шторку
Добавляется TileService с подписью TC и монохромной иконкой. В приложении есть понятная инструкция добавления плитки; на поддерживаемых версиях Android — системный запрос добавления.
Нажатие при заблокированном экране требует разблокировки. Затем startActivityAndCollapse запускает короткий экран захвата; API 34+ использует PendingIntent, предыдущие версии — Intent. Буфер читается только после получения экраном фокуса: Android ограничивает доступ из фона.
Из ClipData принимается непустой текст, с тем же ограничением 65 536 UTF-16 символов, что и существующие входы. Пустой буфер, изображения и недоступный текст дают понятное сообщение без новой задачи. Автоматическое слежение за буфером не добавляется.
Сначала текст надёжно сохраняется в SQLite, затем запускается обработка моделью. Повторное создание Activity не дублирует задачу благодаря сохранённому delivery ID. Новое отдельное нажатие является новым захватом.
PROCESS_TEXT и SEND продолжают работать и используют ту же визуальную обратную связь.

## Анимация создания
После успешной записи показывается небольшая стеклянная карточка с анимированной галочкой, мягким бликом и текстом «Добавлено в бэклог». Затем экран закрывается и пользователь возвращается в предыдущее приложение.
Это подтверждение сохранения, а не завершения работы модели. Ошибка записи никогда не показывает успех. Анимация не требует подтверждения и не блокирует фоновую обработку.
При отключённых системных анимациях показывается короткое статичное подтверждение; состояние остаётся доступным для TalkBack.

## Визуальная система
Палитра: графит, чёрный, белый и серебристые полутона, без зелёного. Основное направление — тёмный графитовый фон с мягкими световыми пятнами и стеклянными поверхностями.
Карточки имеют полупрозрачное заполнение, тонкую светлую кромку, слоистые блики и мягкую тень. Размытие используется там, где Android и производительность позволяют; на остальных устройствах остаётся качественное градиентное стекло. Оптическая реализация Apple Liquid Glass не обещается.
Единые элементы: фон, карточка, кнопки, переключатель фильтров, панель выбора статуса, экран успеха. Плавное появление карточек, реакция на нажатие и завершение задач. Анимации не запускаются заново при каждом обновлении списка.
Главный экран: заголовок TaskCapture, счётчики, фильтры «Все», «Бэклог», «В работе», «Выполнено», список карточек, доступ к экспорту и инструкции плитки. Карточка открывает детали; отдельная доступная галочка завершает задачу, повторное действие возвращает её в бэклог.
Детали: заголовок, описание, выбор статуса, состояние обработки, повтор обработки при ошибке, полный исходный текст.
Размеры адаптируются к узкому экрану и раскрытому Fold. Поддерживаются увеличенный шрифт, безопасные отступы системных панелей, TalkBack, контраст текста и цели касания не меньше 48 dp.

## Статусная модель и сохранность
Существующее поле state — состояние обработки: pending, processing, ready, error. Оно не является статусом задачи.
Отдельное поле status: backlog, in_progress, done. Пользователь может менять его независимо от обработки и возвращать завершённые задачи. Модель меняет только текст и состояние обработки; статус пользователя не сбрасывается.
SQLite version 2 добавляет status с default backlog без удаления таблицы и исходников. Все существующие записи получают backlog. Невалидные статусы отвергаются репозиторием.
Завершение и смена статуса сохраняются сразу и переживают перезапуск. Фильтры и счётчики читают business status, индикатор обработки — state.
Не добавляются удаление задач, синхронизация или редактирование текста.

## Markdown и отправка
Экспорт формирует согласованный снимок ВСЕХ задач, независимо от текущего фильтра, включая pending, processing и error. Задачи сгруппированы по статусам; внутри группы — по времени создания.
Файл UTF-8 .md содержит заголовок, дату экспорта, группы, чекбоксы (- [x] для done), название, описание, время создания, состояние обработки и полный исходник. Если описание ещё отсутствует, задача всё равно присутствует в файле.
Пользовательский текст экранируется так, чтобы заголовки, обратные кавычки и списки не разрушали структуру. Исходник оформляется безопасной цитатой с сохранением строк.
«Сохранить .md» использует ACTION_CREATE_DOCUMENT и выбранное пользователем место. «Поделиться» создаёт файл в отдельной папке cache/exports и передаёт content URI через FileProvider, ClipData и временный read grant, открывая системный chooser. База данных и модель не доступны через provider.
Основной MIME text/markdown. Если на устройстве нет принимающих приложений, предлагается совместимый text/plain. Ошибки сохранения и отправки показываются явно; отмена системного меню не считается ошибкой. Старые временные экспорты очищаются с запасом времени для получателя.

## APK и подпись
Версия 0.2.0 собирается через GitHub Actions только после успешных тестов и публикуется с прямой ссылкой на arm64 APK. Проверяются встроенная модель, native runtime, лицензии и отсутствие INTERNET.
Версия 0.1.0 собрана assembleDebug на временном runner без сохранённого ключа. Восстановление прежней подписи не гарантируется; миграция SQLite сама по себе не делает APK совместимой по подписи.
Перед доставкой проверяется возможность подписания совместимым ключом. Если прежний ключ недоступен, новая APK должна иметь отдельный applicationId и понятное имя версии, чтобы установиться рядом со старой и не требовать её удаления. В этом случае старые задачи остаются в старом приложении; автоматический перенос закрытой базы между приложениями не обещается. Для переноса может потребоваться отдельный ADB-путь, который согласуется с Владом при необходимости.
Будущие обновления должны использовать постоянный ключ. Приватный ключ не коммитится и не публикуется в release; для стабильной подписи нужен защищённый секрет/хранилище CI. Если защищённая подпись недоступна в текущем подключении, ограничение явно указывается, а безопасность данных имеет приоритет над обещанием бесшовного обновления.

## Приёмка
- Захват через реальный путь плитки на доступной версии Android: текст, пустой буфер, фокус, блокировка и повторное создание Activity.
- Сохранение предшествует экрану успеха; задача остаётся при остановке приложения и сбое модели.
- Миграция базы v1 сохраняет количество, ID и исходники; все получают backlog.
- Все переходы статусов сохраняются; поздний ответ модели не отменяет done.
- Markdown содержит все статусы и состояния обработки, Unicode и сложный пользовательский Markdown.
- Сохранение и отправка файла проверяются на устройстве/эмуляторе, provider не открывает файлы вне exports.
- Экраны проверяются визуально со включёнными анимациями, узкой и широкой областью, увеличенным шрифтом; функциональные UI-тесты работают с отключёнными анимациями.
- Существующие unit/storage/offline inference проверки продолжают проходить.
- Финальный APK, Actions run и реальные ограничения подписания предоставляются Владy. Проверку физического Fold нельзя заменять утверждением о проверке на эмуляторе.
