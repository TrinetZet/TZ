# TaskCapture Android — упрощённая версия
Дата: 2026-10-13
Статус: спецификация для просмотра пользователем; приложение и APK ещё не созданы.

## Назначение и согласованные требования
Влад выделяет текст в стороннем Android-приложении и выбирает «Создать задачу». TaskCapture принимает выбранный текст, обрабатывает его локальной LLM и сохраняет задачу в локальный бэклог без экрана подтверждения. Интернет, аккаунт и облачная обработка при использовании приложения не нужны. Windows и горячая клавиша — отдельный следующий этап.

Эта спецификация заменяет для первой Android-версии соответствующие части TaskCapture_TZ_Codex.md: OCR, скриншоты и Windows исключены; подтверждение перед записью заменено автоматической записью по прямому позднейшему указанию пользователя.

## Подходы и выбор
1. Нативный Android (Kotlin, Android UI, SQLite): рекомендуется для первой версии, поскольку главный сценарий — системная интеграция Android, а Windows отложен.
2. Flutter с нативным Android-адаптером: сохраняет исходный кроссплатформенный подход, но добавляет второй UI/runtime и сложность JNI-интеграции локальной модели.
3. Реестр с обработкой правилами: проще и легче, но не выполняет требование реальной LLM; не принимается как готовая версия.

Предлагается вариант 1. Формат экспорта задач будет независим от Android для будущего Windows-клиента.

## Размещение
Репозиторий TrinetZet/TZ, отдельная ветка feat/taskcapture-android.
Каталог taskcapture-android; отдельный workflow .github/workflows/taskcapture-android.yml.
Исходники существующих проектов не изменяются. Отдельный новый репозиторий не требуется.

## Поток захвата
- Экспортированная Activity принимает ACTION_PROCESS_TEXT, text/plain, с подписью «Создать задачу».
- Дополнительная точка входа принимает ACTION_SEND, text/plain: «Поделиться» → TaskCapture.
- Доступность пункта в меню выделения зависит от приложения-источника; нельзя обещать наличие во всех приложениях.
- Пустой текст отклоняется с понятной ошибкой; вход ограничен по размеру, длинный исходник сохраняется целиком в пределах лимита, а обработка получает ограниченный фрагмент с явной отметкой.
- При получении текста он немедленно записывается в SQLite как задача со статусом обработки. Пользователь возвращается в исходное приложение, подтверждение не требуется.
- Модель обрабатывает очередь последовательно. Используется механизм фоновой работы с соблюдением ограничений Android; если ОС откладывает обработку, текст уже сохранён.
- После успешной обработки заголовок и описание обновляются. При сбое задача остаётся с исходным текстом и видимым статусом ошибки; доступны повтор и ручное редактирование.
- Повторный запуск процесса не теряет входной текст и возобновляет незавершённую очередь без создания копии записи.

## Локальная модель
Реальный llama.cpp через JNI, arm64-v8a, компактная русскоязычная instruct-модель семейства Qwen3 0.6B в GGUF Q4.
Веса входят в установочный комплект APK; скачивание модели на телефоне не требуется.
До реализации необходимо проверить актуальный upstream, формат чата, лицензию выбранных весов, воспроизводимый источник и SHA-256. Это инженерная проверка, не повод подменять LLM правилами.
Выход модели ограничивается структурой title/description. Сроки, ответственные и приоритеты не извлекаются в первой версии — это уменьшает риск выдуманных полей.
Сырой текст сохраняется отдельно и не перезаписывается результатом.
Вход — недоверенные данные: фиксированная инструкция, ограничение токенов, структурированный выход и проверка результата. Модель не получает инструментов, доступов к файлам и сетевых функций.
Невалидный или пустой результат не считается успешным.
Если интеграция модели блокируется, результат обозначается как неполный; выпуск без LLM нельзя объявлять выполнением запроса.
Ожидаемый размер APK — сотни мегабайт; точный размер и производительность сообщаются после сборки, без обещаний заранее.

## Реестр первой версии — минимальный бэклог
Русский интерфейс: один список автоматически созданных задач и просмотр задачи с заголовком, описанием и исходным текстом.
Отображаются только состояния обработки: ожидает, обрабатывается, обработана, ошибка. При ошибке доступен повтор.
Нет ручного создания, импорта/экспорта, поиска, проектов, приоритетов и статусов рабочего процесса.
SQLite: стабильный ID, дата создания/изменения, title, description, source_text, processing_status, error_code, попытки обработки.
Транзакционные изменения и восстановление очереди после перезапуска.
Windows следующим отдельным этапом: выделение текста → настраиваемая горячая клавиша → локальная LLM → автоматическое добавление в бэклог без подтверждения.

## Конфиденциальность
Приложение не запрашивает INTERNET, доступ к контактам, Accessibility или чтение чатов.
Нет аналитики и удалённых API.
Данные сохраняются в приватном каталоге приложения. Автоматический системный бэкап базы отключён.
Экспорт не входит в первую версию.

## GitHub Actions и установка
Workflow собирает arm64 APK на Linux runner с Java/Android SDK/NDK, получает зафиксированные зависимости и веса во время сборки.
Проверяет хэш весов, запускает тесты, собирает подписанный APK, публикует артефакт с SHA-256 и отчёт проверки.
Для тестовой установки допустим debug-подписанный APK с явным обозначением; стабильный release требует сохраняемого ключа, приватный ключ не коммитится в публичный репозиторий.
Пользователь получает ссылку на конкретный завершённый успешный Actions run и APK-артефакт. Для скачивания артефакта может требоваться вход GitHub и распаковка ZIP.
При наличии безопасного пути публикации релиза дополнительно предоставляется прямая ссылка на APK.
Успешная сборка не заменяет тест на реальном телефоне.

## Проверки и приёмка
- Unit: валидация входа/выхода, сохранение исходника, ошибки JSON, ограничение размера.
- Integration на Android: PROCESS_TEXT и SEND → SQLite → обработка → чтение после перезапуска; повтор очереди без дублей.
- Реальный локальный инференс на синтетических русских поручениях; результаты не подменяются mock-ответами.
- Проверка сохранения задачи при ошибке модели и перезапуске процесса.
- Список и просмотр автоматически сохранённых задач после перезапуска.
- Проверка манифеста APK: нет INTERNET; локальная модель реально упакована.
- GitHub Actions завершён успешно, APK существует, размер и SHA-256 опубликованы.
- На телефоне Влада: установка, авиарежим, выделение текста в совместимом приложении → задача в реестре; отдельно проверяется путь «Поделиться».
- Отчёт чётко различает автоматические проверки, эмулятор и ещё не выполненную проверку реального устройства.

## Самопроверка спецификации
Требования согласованы с последним пользовательским сценарием: Android первым, текст вместо OCR, реальная локальная LLM, автосохранение без подтверждения.
Нет готовых исходников и APK; этот документ их не заменяет.
Следующий этап после просмотра спецификации — конкретный план реализации и его исполнение с проверкой сборки.
