# Three difficulty levels Implementation Plan

> **For agentic workers:** Use executing-plans for integration, with delegated independent content authoring and final review as explicitly authorised.

**Goal:** useful, context-sensitive practice without length guessing and with separate honest progress.
**Architecture:** preserve legacy catalog; new catalog combines existing metadata with two independent authored content modules. Pure state/attempt functions isolate migration, permutation and profiles; UI consumes selected level.
**Tech Stack:** existing ES modules, Node tests, Playwright, Android Java/WebView and CI.
**Spec:** docs/superpowers/specs/2026-10-04-levels-design.md

## Global Constraints
- 12 topics × 3 levels × 3 decisions; 324 credible responses.
- UI English, guide RU/EN separate preference; no CEFR/AI grading claim.
- Same storage key/package/signing key; Android 1.1.0 code 3.
- Existing legacy answers/history/reviews/drafts preserved, no expert credit.
- Public release and website verification required, root HTML preserved.

## Review Focus
- v1 partial attempts and malformed v2 orders must not corrupt score mapping.
- storage failures must allow export of current in-memory data.
- old imported high scores must never inflate Expert profile.
- shuffled ties and length/position heuristics must not yield trivial 100%.
- review all plausible responses against explicit facts, not assumed hidden constraints.
